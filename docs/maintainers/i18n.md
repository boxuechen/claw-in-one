# Android interface language

ClawInOne ships two interface languages: English (`en`) and Simplified Chinese
(`zh-CN`). English is the default and fallback language. Existing language choices
are preserved when upgrading; an installation without a saved choice migrates to
English.

Run `node scripts/android-i18n.mjs sync` after adding user-facing text through
`nativeString`, `nativeStringResource`, or `nativeText`. Add every new Simplified
Chinese translation to `apps/android/app/src/main/i18n/zh-CN.json`; generated XML
and `NativeStringResources.kt` must not be edited directly. Run
`node scripts/android-i18n.mjs check` to verify call-site coverage, locale parity,
format placeholders, generated output, and the supported resource directories.

## Translation boundary

Keep product and developer terms in English when that is the clearest form:
ClawInOne, OpenClaw, Gateway, Node, Plugin, Skill, Provider, Android Use, API key,
CLI, Web UI, protocol fields, permission identifiers, commands, URLs, and model IDs.
Translate actions, status and error text, loading and waiting states, permissions
and risk explanations, onboarding and recovery guidance, settings navigation, form
help, and validation errors.

Use these product terms consistently in Simplified Chinese:

- Thread → 对话
- Session → 会话
- Approval (request or noun) → 审批 / 审批请求
- Approve (verb) → 批准
- Allowed → 已允许
- Run → 任务 when it means an agent task; 执行 when it means command execution

Chinese copy does not need to mirror English word for word. Prefer natural,
concise developer-facing language while preserving technical tokens exactly.
